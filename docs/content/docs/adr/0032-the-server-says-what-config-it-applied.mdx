---
title: ADR-0032 — The server says what config it applied
description: /healthz reports the digest of the config applied last and the removals the guard refused, so whoever rewrote the file can tell when it took effect.
---

Status: proposed (2026-10-29) · Supersedes: — · Superseded by: —

## Context

Since ADR-0031 the server reloads its config file by itself. Whoever rewrote
the file — a Kubernetes operator, typically — still cannot tell when a replica
took the change: `/admin/reconciliation` is aggregate, in-memory, and needs an
admin OIDC token. And a removal refused by the `max_removals` guard shows up
only in a log line and the `reconcile_removals_refused_total` metric, so a
deleted resource would look gone while its channel stays managed.

## Decision

**`/healthz` reports the digest of the config the replica applied last and the
ids of the removals the guard refused in that pass.** `/healthz` stays
unauthenticated: a digest and object ids are not secrets, and it is never
routed through the ingress.

- `config.digest` is the lowercase hex SHA-256 of the file's bytes as
  `config::load` parsed them (one read, so it is never of a later write), and
  `null` without a file; `config.applied_at` is when that file was loaded.
- Both advance only when a reconcile pass runs with that file. A file loaded
  but not applied — the replica stood aside, lost the lock, or the reload's
  trust policies did not build — leaves the previous digest, as does a file
  that fails to load.
- `config.pending_restart` is `unreloadable` of that file against the
  configuration the replica **booted** with, not the running one: the running
  one has already adopted trust-policy issuers no verifier was built for.
- `config.refused` is `{ channels, service_accounts }` from the last pass that
  ran, and empties on the next one the guard allows.
- In memory, per replica; no database call, so `/healthz` stays a liveness probe.

## Consequences

**Positive**

- The operator confirms a change pod by pod, and keeps a finalizer on a
  resource whose removal was refused.

**Negative**

- Refused ids on an unauthenticated endpoint leak channel and account ids to
  anyone who can reach the pod port; the NetworkPolicy is what keeps that
  in-cluster.

**Accepted debt**

- No per-object reconcile result (a binding waiting on a first login still
  looks applied). Revisit if the operator needs to report it.
